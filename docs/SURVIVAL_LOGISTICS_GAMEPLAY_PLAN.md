# 生存、傀儡后勤与野外招募：玩法及实施交接

日期：2026-09-21。

状态：设计交接，准备实施。本文记录本轮确认的目标、开发建议和待定项，**不表示新玩法已在代码中完成**。本次交付仅修改文档。

## 1. 使用范围与规则优先级

在现有 Three.js 项目上制作新的 3D 俯视角生存游戏，复用美术、战斗、能力、Buff、寻路和交互基础；不另起空项目，不继续围绕抽牌和波次修补主循环。

- 本文是新玩法的实施入口。与旧卡牌、波次、军需铺方案冲突时，按本文已确认规则实施。
- `RUNE_STONE_GAMEPLAY_PLAN.md` 保留为旧版设计与实现记录；其中死亡不掉落、附魔卡生成石头等规定不再约束新玩法。
- `ARCHITECTURE.md` 用于定位现有代码，不代表新玩法已经存在。通用性能、UTF-8、VFX、修改范围和验证要求继续适用。
- 下文明确区分“已确认”“实施建议”“待定”。示例数字不是已批准的平衡值；建议不应被写成用户已确认要求。
- 未被本次讨论覆盖的旧规则，不自动升级为新游戏要求。尤其不要为了复用代码而重新引入波次、抽牌、卡牌能量或 Boss 商店。
- 不因实施本方案擅自提交、推送或部署；这些操作仍需用户明确要求。

## 2. 核心体验与已确认边界

主循环：

```text
安排采集 → 制作工具与装备 → 组织生产和运输 → 招募、装备战斗单位
    ↑                                              ↓
扩大劳动力与供能 ← 获得刷怪点掉落、开放安全资源区 ← 推进并摧毁刷怪点
```

### 2.1 已确认

- 游戏不再使用波次流程；地图上的刷怪点持续产生怪物压力。
- 最终挑战目标是清除地图上所有刷怪点。
- 开局有一个基地、一个木傀儡，以及一些木头和石头。
- 木傀儡有背包、武器槽和独立的活动魔力条。
- 新增傀儡的来源与刷怪点掉落挂钩，不采用只靠普通木石无限制造傀儡的默认方案。
- 原战斗兵种保留，在野外遇到并招募；能够装备附魔石，武器只能更换为同类武器。
- 玩家可以手动转移物品并绕过运输系统。自动物流的价值是持续代劳，不是强制所有物品走运输。
- 所有单位死亡后，背包中的物品掉落。
- 卡牌系统退出新玩法；战斗、能力、Buff 系统保留，能力后续通过基地科技树获得。
- 有可合成、可摆放的功能建筑，包括箭塔、食堂，以及后续生产、能源和科研设施；不据此扩展出房屋墙体等自由建造系统。
- 不做传送带。容器之间由玩家指定转移目标，傀儡实际取货和搬运。

### 2.2 防止实现时走回旧方案

| 旧规则或曾提出的建议 | 新玩法处理 |
| --- | --- |
| 开局按道路抽单位卡、每波发牌 | 删除此获取流程；开局固定木傀儡，战斗单位野外招募 |
| 普通木石直接制造第二个傀儡 | 新增傀儡来源改为刷怪点掉落；成品或核心待定 |
| 远距离手动拖物品只能创建配送任务 | 不采用；明确允许玩家手动绕过物流 |
| 符文死亡后留在原单位档案 | 改为物品落在场景中，保留原实例数据 |
| 凯旋成长只保存在单位 Buff | 改为保存在对应附魔石实例中，随石头转移 |
| 附魔卡消耗卡牌能量生成符文 | 新玩法取消卡牌来源；后期通过附魔台制作 |
| Boss 后专精选择、军需铺、下一波按钮 | 不作为新主循环入口；专精若保留，解锁途径另定 |
| 卡牌能量与旧出售返能量规则 | 不自动继承为新的魔力经济或物品售价 |

## 3. 基地、魔力与活动范围

### 3.1 已确认

- 基地为周围约 20m 范围提供魔力，该半径做成配置参数。
- 基地供能有功率上限，需要考虑多个单位、设施同时使用的总负载。
- 木傀儡活动使用自身魔力，魔力与现有武器耐力/耐久资源分开。
- 蓝色魔力条显示在武器耐力条下方；不得用魔力条替换原武器条。
- 箭塔、食堂等功能建筑使用魔力提供作用；后续魔力炉消耗燃料，为附近提供魔力。

### 3.2 建议采用的供能模型

| 数据 | 含义 |
| --- | --- |
| `manaCapacity` / `manaStored` | 傀儡的魔力容量与当前储备 |
| `supplyPerSecond` | 基地或魔力炉每秒可提供的魔力 |
| `supplyRadius` | 能接受该供能源补充的范围 |
| 行为消耗率 | 移动、采集、搬运、战斗等行为的魔力消耗 |
| 设施工作耗能 | 设施提供作用时的消耗；待机耗能另行配置 |

建议让傀儡用自身储备工作，在供能区获得补充；离开范围后仍能活动，但无法继续从该供能源补魔。不要将离开 20m 直接实现为禁止行动。

能量守恒约束：在时间段 `dt` 内，分配给所有接收者的魔力之和不能超过供能源当段实际可提供的 `supplyPerSecond × dt`。不能给范围内每个单位各发一份完整功率，也不能把同一单位的工作消耗重复扣除。

例如供能 10/秒，傀儡合计消耗 6/秒，工作的箭塔消耗 3/秒，余量为 1/秒。此例仅解释供需，不是初始数值配置。

建议任务开始前估计工作和返程用量，保留返程储备；低魔力时主动回到可用供能区。正常自动任务不应反复把傀儡困在远处。供能不足、断燃料和等待补魔需要明确的 UI 状态。

待定：负载不足时的分配策略、多供能源重叠规则、最大充能速率、耗尽后的停机/救援行为、普通战斗单位是否也使用活动魔力。不要擅自把木傀儡魔力规则推广到所有兵种。

旧符文升级资源也叫“魔力”，实现时必须与活动魔力分开字段、计量和 UI 文案；建议将前者显示为“符文经验”，最终名称待定。基地补魔不能顺带刷符文经验。

## 4. 背包、合成与快捷栏

### 4.1 已确认交互

- 按 E 打开基地背包界面：中间为背包，左边为资源列表，右边为可合成列表。
- 资源列表下方有优先级格子，玩家将资源拖入格子，安排自动采集需求。
- 悬浮资源显示采集所需工具及条件；例如砍树需要木斧、挖矿需要木镐。
- 点击配方后，鼠标携带对应物品预览；拖入背包时消耗材料并获得物品；右键取消。
- 点击单位同时打开单位与基地背包，交互参考已有符文背包，可以把工具、武器和附魔石拖给单位。
- 下方手牌区域改为物品快捷栏，支持按物品类型拖给单位、拖到地图或者使用。
- 手动转移允许绕过实际运输，不增加距离、交战状态或配送等待限制来否定这条规则。

### 4.2 实施约束与建议

- 点击配方时只生成预览，成功落入合法目标时才扣材料和生成实物；取消或无效落点不得扣费。
- 合成必须同时校验材料、库存空间和目标合法性，避免扣材料后无法放入。
- 普通资源可堆叠；附魔石等携带独立成长数据的物品按实例管理，不按名称合并。
- 快捷栏建议引用实际库存物品，不生成第二份所有权；库存不足或物品已经转移时及时刷新。
- 区分“资源清单中的采集需求图标”“配方预览”和“实际库存物品”，拖动需求图标不能凭空产出资源。
- 对地图拖放按物品类型处理：掉落物、功能建筑放置预览、消耗品使用各自校验，不把所有物品都视作建筑。
- 允许手动搬运不等于允许复制。手动转移与傀儡取货冲突时，只能有一方成功取得同一份货，另一方重新规划。
- “玩家背包”当前按基地库存界面理解；是否额外存在独立玩家库存、快捷栏归属及跨容器快捷操作，需要在 UI 阶段定稿。不自动新增可控人物。

## 5. 采集、工作比例与运输

### 5.1 已确认

- 场景中的树木、石头、矿石等作为有限资源，采集后会耗尽。
- 单位根据玩家需求优先级和自身工具条件自动工作。
- 优先级使用百分比表达，用户示例为第一项 50%、第二项 25%；剩余槽位数量和权重规则未定。
- 采集物进入单位背包，随后自动存入附近容器。
- 玩家可以指定容器的转移目标，傀儡负责把物品搬过去，运输不需要工具。

### 5.2 推荐实现，需保留可调整性

- 将百分比解释为一段时间内的采集工作投入比例，并提供库存目标；不要仅按物品件数比较木头和矿石。
- 单傀儡完成一批工作后再调整，多傀儡可分头承担需求；不要每帧随机切换资源。
- 某项达到库存目标、缺工具或没有可达资源时暂时跳过，在可执行需求之间重新分配。
- 以上“工作比例＋库存目标”是推荐解释。用户原话是获得资源的百分比，在实现调度器前需定稿，不能默认为已确认的精确算法。
- 附近容器必须有容量且允许该物品进入；不能只找几何距离最近但不可达或已满的箱子。
- 容器连接建议包含物品过滤和目标库存上限，目标满足后停止搬运。连线表示运输关系，寻路仍由现有导航处理。
- 对同一资源节点、货物数量、目标空位进行任务预留；手动移动、容器销毁、单位死亡或任务取消时释放预留。
- 避免容器互相倒货。最小版本可以限制自连接和循环运输；具体限制方式应在 UI 中提示。

工作调度需要区分生存与生产：受到威胁时逃跑或自卫、低魔力返程、满包卸货、补充关键燃料、普通运输、普通采集不能共用一个简单百分比列表。具体优先级可配置，避免固定排序导致长期饿死某类任务。

建议傀儡同时携带常用工具并自动选择，不要求玩家每次伐木/挖矿都手动换装；工具占格、工具槽和武器槽的关系待定。没有武器时遇敌逃跑，有武器时战斗；自卫不要无限追击而放弃工作，主动进攻命令仍由玩家控制。

可见状态至少覆盖：缺少工具、资源耗尽、没有有效任务、容器已满、路线不可达、供能不足、正在补魔、正在采集和正在运输。

## 6. 刷怪点、傀儡来源与战斗招募

### 6.1 已确认

- 持续怪物压力来自地图刷怪点，目标是清除全部刷怪点。
- 新增傀儡来源是刷怪点掉落；不是抽单位卡，也不默认只花普通木石合成。
- 原有战斗单位可在野外发现并招募；兵种特性、能力与自动战斗保留。
- 战斗单位可装备附魔石，武器只能换成同类武器。

### 6.2 实施建议与未定边界

- 建议摧毁刷怪点永久停止该点产怪，保存其清除状态；不是只杀死当前一批敌人。
- 每个点配置生成间隔、活动/出击规则、存活上限与掉落，避免无限堆怪。移除波次不等于每帧无上限生成。
- 出生区提供足以启动工具和武器制作的资源及准备空间；后续资源区通过推进取得。
- 建议早期有可预期的劳动力扩充机会。是否必掉、哪个点掉、掉成品还是制造核心均待定。
- 野外招募的发现方式、费用、条件、人数限制与招募后控制权待定，不擅自规定付费、营救或对话模式。
- 建议主要由傀儡采集运输，战斗单位负责护卫进攻；普通兵种是否也能工作尚未确认。
- 同类武器用配置标识如 `weaponFamily` 校验，不依赖物品名称字符串。弓可换另一把弓；具体家族划分待定。
- 换武器时保留兵种身份，检查攻击动画、投射物、射程、攻击事件和耐力参数兼容，不能只改模型。

需要在完整试玩前确定胜负边界：最后一个刷怪点被毁但还有怪物时是否立即胜利；基地被毁、初始傀儡死亡且尚无替代来源时如何失败或恢复。不能让局面已经无法继续却永远不结束。

## 7. 死亡掉落与物品守恒

已确认：**所有单位死亡后，背包中的东西掉落。** 不继续采用符文挂在死亡单位档案中的旧方案，也不自动传回基地。

- 掉落的是原物品及数量；附魔石保持原实例 ID、等级、经验和累计成长。
- 死亡结算后，原背包不再拥有这些物品，场景掉落容器或掉落物成为新位置。
- 拾取是位置/归属转移，不是再生成一份副本。单位重复死亡通知、对象回收、重生或加载不能重复掉落。
- 地面上的附魔石不对原单位或附近单位持续提供属性加成。
- 死亡时中断工作、释放任务预留。已经搬到背包里的货物跟随背包掉落，尚未取出的货物留在源容器。
- 敌方单位若拥有实际背包也遵循规则；不要据此把所有装饰武器模型自动生成额外战利品。

推荐将武器槽、工具槽、附魔槽内的实际物品一起掉落，统一为可拾取遗物包，避免视觉拥挤；这是对“背包物品”的实现建议，装备槽范围与散落/遗物包表现仍需定稿。

掉落物的存留时间、是否允许远程手动拾取、自动拾取任务和联机归属待定。已允许手动跨背包转移，不据此自动推断地图上所有战利品无条件远程入库。

## 8. 附魔石是成长数据的唯一持有者

### 8.1 已确认规则

- 附魔石能够装备、取下和转交；石头产生的永久成长记录在石头中，不记录为单位自身永久属性。
- 凯旋累计增加的最大生命值必须随对应石头一起转移，新持有者直接享受已有成长。
- 死亡掉落不重置成长，不将成长留在死亡单位上，也不按新持有者重新练一遍。
- 单位自身基础属性和自身培养，与石头贡献分开，不能把单位的全部成长都转存进石头。
- 后续解锁附魔台制作附魔石，不再依赖附魔卡生成。
- 延续此前已确认且本轮未替换的成长规则：单位击杀获得的符文成长资源在参与成长的石头之间均分；法术等非单位击杀不产生该资源。怪物提供的量在生成时依据难度确定，但新模式不再使用波次作为难度来源。

### 8.2 凯旋验收例

仅说明附魔石加成，排除其他 Buff：

1. 石头 S 的凯旋累计最大生命加成为 40，A 的基础上限为 100，B 的基础上限为 200。
2. S 在 A 身上时，A 上限为 140。
3. 转给 B 后，A 上限恢复 100，B 上限变为 240；S 的累计值仍为 40。
4. B 再触发一次成长，只更新 S 的累计值；移给其他人时携带该最新值。
5. B 死亡，S 落地；拾回后等级、经验、累计值和身份不变。
6. 两块同名石头 S、T 的成长互不污染；不能按附魔类型共用一个累计字段。

### 8.3 实施建议

- 物品实例记录附魔种类、等级、经验、永久成长和必要的持久计数；字段名可按现有代码调整。
- Buff 作为石头效果的运行时投影，通过 `runeStoneId` 关联石头；永久成长写回石头，属性修改器按石头实例区分来源。
- 卸下石头只移除该石头贡献，不改坏单位基础值，不删除其他同类来源的增益。
- 凯旋击杀时的即时治疗与累计上限分开：即时治疗可以作用于当前持有者，但转移不是再次击杀，不重复触发治疗。
- 推荐增加上限时不因装备操作凭空补血；卸下导致当前生命超过新上限时进行上限裁剪。全体类似效果采用一致的资源同步规则。
- 需要延续的永久成长进度随石头保存；临时层数、冷却和持续效果逐项审计，明确是否跨持有者保留，不能把整个 Buff 对象盲目塞进石头。
- 保存、加载、网络快照、掉落、拾取和转移必须覆盖新字段。不能仅在内存转移时看似正确，重新加载就丢失成长。

活动魔力与升级经验必须独立。均分和非单位击杀不产经验沿用已确认规则；新生存模式的经验数值、怪物难度标尺、同名备用石是否参与成长和槽位上限在第 13 节列为待定，不从旧波次难度直接套用。

## 9. 后续生产、能源与科技链

以下方向已确认，但不要求全部塞入首个可玩版本：

| 内容 | 作用与关系 |
| --- | --- |
| 箭塔、食堂 | 合成后放置，使用魔力提供对应作用；具体作用沿用/调整范围另定 |
| 树坑与种植 | 单位取得种子/树苗，种植、等待生长、砍伐，获得木材和后续种植材料 |
| 熔炉 | 加工木材得到燃料；建议木材产物命名为木炭，地下煤矿产物另称煤 |
| 魔力炉 | 消耗燃料，为周围生产和战斗提供魔力 |
| 科研站与基地科技 | 投入资源解锁科技、更高级装备和能力 |
| 附魔台 | 科技解锁后制作附魔石 |

实施时检查整个链的净产出：种植、采集、加工、搬运和供能的总消耗之后，必须还有可支持其他活动的产出。保证第一批燃料有启动路径，不出现所有环节都等待尚未生产的燃料。

建议种植材料有保留量，避免把下一轮种植所需资源全部加工掉。树场只解决木材再生；石头和矿石耗尽后是继续找新矿、使用深层矿井，还是有限地图资源足够通关，尚未决定。

不额外引入未讨论的饥饿条、复杂食谱、输电线、传送带或自由房屋建造。功能设施放置仍应遵循占地、导航和世界遮挡规则。

### 10.1 已发现的具体改造点

- `BuffSystem.js` 的 `triumphOnKill` 当前把成长写入 `context.buff.triumphHealthBonus`；必须改成对应石头实例为持久来源。
- `UnitEntity.js` 当前保留/恢复 Buff 的 `triumphHealthBonus` 并重建属性修改器；迁移后不能再独立维护另一份累计值。
- `runeStones.js` 的 `normalizeRuneStone()` 与 `serializeRuneStone()` 当前未包含永久成长字段，位置类型仅覆盖基地/单位；需覆盖成长以及通用库存/掉落位置，防止未知位置被静默改回基地。
- `RuneStoneSystem.handleUnitDeath()` 当前记录 `strandedUnits`；新模式需转为真正的场景掉落。旧 `reassignUnitStones()` 与重生流程也要审计，防止把已掉落物品再次发给重生单位。
- 当前 `activeStonesForUnit()` 允许同名备用石，只激活其中一块；这与旧文档早期“同名只能携带一块”不同。不要凭代码现状或旧注释擅自认定新规则，实施附魔阶段应明确容量及同名策略。
- 旧符文生成/售价仍依赖卡牌能量相关字段。新物品经济不能为了保留这些字段而重新引入卡牌能量。

### 10.2 迁移方式建议

先建立新生存会话入口，使其不进入旧抽牌/波次流程，接通复用系统；再按引用关系清理已失去用途的旧代码。最终新玩法不保留隐藏的波次推进与抽牌副作用。是否继续维护可玩的旧模式尚未确认，不默认要求双模式长期兼容。

不要仅隐藏手牌 DOM 就认为已经移除卡牌系统。检查初始化、更新循环、输入监听、快捷键、HUD 查询、奖励弹窗、结束流程、网络命令和存档恢复路径。

旧存档迁移或版本隔离需要显式处理，不静默删除用户存档，也不把旧波次局按新生存局直接加载。

## 11. 数据与系统实现约束

以下是建议职责划分，具体文件名可由实施者按现有结构调整，不要求照名新建大量空壳。

| 职责 | 必要数据/规则 |
| --- | --- |
| 物品定义与实例 | 定义 ID、类别、堆叠限制、工具条件、武器家族；成长装备有唯一实例 ID |
| 库存与装备 | 所属实体、容量、槽位、物品数量；每个实例同时只位于一个位置 |
| 合成 | 输入、输出、解锁条件；一次事务检查并扣料、入库 |
| 资源节点 | 稳定 ID、资源种类、剩余量、工具条件、采集点和导航关联 |
| 工作调度 | 需求、权重、任务所有者、预留量、阶段、失败原因及重试条件 |
| 运输关系 | 源容器、目标容器、过滤条件和库存阈值 |
| 供能 | 供能源、范围、功率、接收者需求、储备和实际分配 |
| 刷怪与招募 | 刷怪点清除状态、生成规则、掉落记录、野外单位招募状态 |
| 掉落 | 原物品到世界位置的所有权转移，防重复拾取/掉落 |
| 附魔成长 | 石头实例的等级、经验、永久收益与持久进度，Buff 只提供运行时效果 |

性能与正确性要求：

- 用事件、需求变化和任务队列驱动工作，配合空间查询；不要每个傀儡每帧扫描所有资源和容器。
- 先筛选任务，再对实际候选寻路；不要为全场候选逐个跑 A*，也不要目的地不变仍反复寻路。
- 采集完成、树木长成、建筑放置/移除时更新对应导航阻挡，不重建整个世界对象集合。
- 模型、材质、几何和高频特效尽量共享；资源节点要有独立逻辑 ID，不能将实例化渲染索引当作永不变化的存档身份。
- 合成、手动转移、自动搬运、死亡、拾取和成长经过统一的数据变更入口，防止 UI 直接改数组绕过校验。
- 如果支持联机，所有物品变更、魔力分配、资源枯竭、掉落、招募和刷怪清除由 Host 裁定；客户端发送意图并接收结果，覆盖重复命令、同时拾取和断线同步。

## 12. 建议开发顺序与阶段验收

### 阶段 A：新会话与物品基础

- 接入无抽牌、无波次的新开局：基地、木傀儡、初始木石。
- 建立通用物品、库存、工具/武器、E 界面、合成预览和快捷栏。
- 接通手动跨背包转移，允许绕过运输。
- 验收：可制作并交付工具；取消合成不扣料，满包不吞材料，转移不复制物品，旧发牌/奖励不会被动弹出。

### 阶段 B：采集、运输与供能

- 接入有限树木、石矿、工具校验、需求比例、附近卸货和容器转移。
- 接入活动魔力、蓝条、基地功率与自动返程。
- 验收：傀儡能够完整采集—卸货—运输—补魔；没有工具不采集，不向满箱无限搬货，手动抢先取货后 AI 正确重新规划；总供能不超功率。

### 阶段 C：战斗、探索与胜负闭环

- 接入持续刷怪点、清除目标、傀儡来源掉落和至少一种野外战斗单位招募。
- 接通武器同类更换、无武器逃跑/有武器自卫，以及主动进攻。
- 接通死亡物品掉落、拾取与失败规则。
- 验收：从初始一个傀儡出发，能扩充劳动力、招募战斗单位并清除全部刷怪点；死亡/无资源等情况不会形成无法继续却不结束的软锁。

阶段 A～C 构成首个完整可玩版本。不能用“普通木石造第二个傀儡”替代已确认的刷怪点掉落来源。

### 阶段 D：附魔成长迁移

- 将石头纳入通用物品体系，完成凯旋及所有同类永久成长的归属审计。
- 验收：第 8.2 节示例、换石、反复转移、死亡拾回、序列化往返均保持成长且不重复叠加。
- 这是物品数据设计的前置约束；若前三阶段暂未提供正式石头来源，可在开发测试中生成石头验证，不能据此恢复附魔卡作为正式来源。

### 阶段 E：可持续生产和科技扩展

- 加入功能建筑、树坑种植、木炭加工、魔力炉、科研及附魔台。
- 验收：生产链可以从初始资源启动，燃料供能有净收益；缺燃料/缺树苗原因可见，科技解锁真正进入配方/能力流程。

每阶段修改游戏代码后做相应语法检查、构建和针对行为的验证。优先测试物品守恒、状态转移、功率守恒和成长持久化，而不是只测试 UI 是否存在。最终在实际俯视相机下完整试玩，检查单位状态、魔力条、拖放、路径、危险与掉落辨识。静态检查通过不代表玩法或实际运行已验收。

本次仅文档修改，不以运行旧版游戏构建充当新玩法实现验证。

以下事项不阻止先搭建物品和会话基础；涉及该机制的实现前应给出明确取值或经用户确认的规则。一般平衡数值可先用注明用途的配置默认值，不必为每个数字停工；影响玩法含义的选择不能冒充已确认决定。

| 事项 | 实施前需要确定的内容 |
| --- | --- |

| 采集百分比 | 工作投入比例还是产出数量比例，余下权重如何分配，库存目标及统计范围 |
| 背包和快捷栏 | 格数、堆叠、装备/工具槽、玩家库存是否独立、快捷栏引用位置 |

| 死亡与拾取 | 装备槽是否全部掉落、遗物包形式、存留时间、拾取距离和联机归属、重生兼容 |
| 刷怪与胜负 | 生成上限与节奏、残余敌人的结算、基地毁坏/唯一傀儡死亡的失败或补救 |
| 恢复机制 | 旧的基地不回血/不回耐久、全局被动耐久恢复如何适配；本轮未要求基地供魔同时治疗 |
| 附魔规则 | 新怪物经验标尺、同名石头与备用石、容量、临时状态归属；均分与非单位击杀不产经验沿用已确认规则 |
| 建筑与再生 | 配方和消耗、种植产率、生长时间、树苗保障、石矿后续来源及高级燃料 |
| 科技与旧专精 | 研究费用和前置、能力获得、旧专精是否并入科技；不再依赖 Boss 军需铺 |
| 存档和联机范围 | 旧存档迁移/隔离，首版是否提供联机，新库存/基地的共享及所有权规则 |
