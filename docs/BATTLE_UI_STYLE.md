# 战斗 UI 视觉规范

本文记录当前战斗场景已经采用的 UI 语言，供后续主菜单、图鉴、商店、结算、联机大厅等界面逐步统一。它是一套视觉与材质规范，不要求所有页面复制战斗 HUD 的布局。

## 核心定位

- 低多边形实体桌游组件，而不是手机游戏面板。
- 高级独立策略游戏质感：克制、清楚、可靠，有轻微手工模型感。
- 暗色哑光主体、冷灰金属边、柔和环境阴影，少量暖色或青绿色功能强调。
- UI 像摆在战场上方的实体棋盘零件，但文字与状态必须优先清晰可读。

## 基础材质

### 主体

- 顶面：`#414442` 至 `#303332`
- 深面：`#262928` 至 `#1d211f`
- 最深内衬：`#171a19`
- 主边框：`#706e67`
- 亮边：`#aaa292`
- 主文字：`#eee4d3`
- 次文字：`#aaa79f`

面板通常使用两层渐变：顶部保留很弱的亮面，底部加深。不要使用玻璃拟态、大面积透明模糊或发光描边。

军需铺、暂停、波次奖励等大弹层禁止使用贯穿面板的大面积斜向反光；只保留窄顶部亮边和极弱的哑光颗粒。背景模糊控制在约 `1–2px`，避免弹层呈现半透明玻璃感。

大弹层因面积更大，主体色要比小型 HUD 更深，建议从 `#303330` 过渡到 `#181b1a`；不要用大面积中灰色维持可读性，亮度应集中在文字、金属边和功能令牌上。

### 形体

- 大面板使用 7–10px 切角。
- 卡牌和小按钮使用 3–9px 切角。
- 圆角只用于真正需要表达圆形物件的状态，不把所有矩形统一做成圆角卡片。
- 轮廓必须清晰，边框一般为 1–2px。

### 厚度与阴影

实体厚度由三部分组成：

1. 顶部 1px 柔和亮边。
2. 底部 3–5px 深色实体厚度。
3. 外部柔和投影，避免大范围黑色光晕。

推荐阴影结构：

```css
box-shadow:
  inset 0 0 0 1px #171a19,
  inset 0 1px 0 rgba(255, 255, 255, 0.08),
  inset 0 -4px 0 rgba(8, 10, 9, 0.2),
  0 4px 0 #171919,
  0 11px 18px rgba(6, 8, 8, 0.42);
```

## 功能色

- 能量与友方功能：冷青灰 `#6d9995`、`#b9d1cd`
- 波次危险：柔和砖红 `#d19279`
- 时间和奖励：低饱和暖金 `#d2b981`
- 普通边框不使用高饱和功能色；功能色只标记图标、选中状态、能量格或危险等级。
- 禁止所有模块共用同一种高亮色。

## 组件规则

### 顶部波次面板

- 只显示当前波次、波次组成与附魔、目标剩余时间。
- 波次是主信息，资源数据不塞进顶部面板。
- 附魔表现为实体小令牌：独立图标、名称、简短效果，并按效果类型区分颜色。

### 手牌

- 保留卡面插画作为视觉中心。
- 外壳使用暗色哑光材质，插画框、费用徽记和底部说明区共享同一金属边语言。
- 手牌插画窗口使用当前初版高度的约 60%，保持卡牌整体宽度不变，把更多纵向空间留给名称与描述。
- 费用使用多边形实体徽记，不使用普通圆形气泡。
- 费用徽记使用连续外框层包裹内芯，不在裁切多边形上直接画边线，避免倒角处断线。
- 有使用次数的牌在卡面左侧显示窄型实体次数轨；卡面和描述区同步缩窄，使“次数轨 + 内容区”的组合视觉中心仍落在卡牌中央。
- 空牌位是暗色凹槽组件，不使用纯透明占位。
- 手牌后方不增加无功能的底座横条。

### 能量

- 位于手牌正上方，使用水平条状组件。
- 每一点能量对应一个独立格，必须能快速数清当前值和上限。
- 已填充格使用冷青材质；空格保持深色，但轮廓仍可辨认。

### 按钮

- 默认使用暗色哑光顶面、金属边和 3–4px 实体厚度。
- 悬停时只轻微提亮并上移，按下时压低厚度。
- 图标应表达实际功能。商店使用店铺门面图标，设置使用齿轮，不用同一个图标代替不同功能。
- 桌面端抽牌堆和弃牌堆贴近左右下角，并与手牌底边对齐，不悬浮在战场中段。

### 信息面板与弹窗

- 单位信息、军需铺、暂停和奖励弹窗沿用相同材质层级。
- 内容多时优先用间距、分隔线和字号建立层级，不用“卡片套卡片”。
- 奖励、危险、禁用等状态可以改变局部功能色，但不改变整个面板底色。
- 军需铺入口使用中世纪路边行商车图标，明确表现双轮木车、车斗和帆布阳篷。展开面板直接复用顶部波次 HUD 的深灰黑铁、冷灰内凹模块和小铆钉语言；商品项使用低边框功能模块与倒角金属徽章，不使用木板、皮革、棚布、大型装饰徽章或密集网页线框。
- 暂停面板沿用同一暗色外壳、切角、铆钉和实体厚度；设置区表现为内嵌控制槽，只有“继续”按钮使用克制的冷青功能色。
- 波次奖励使用三张横向实体战争卡：共享暗色切角黑铁外壳，直接展示卡牌自身的卡面插画、卡牌种类和类型主题色，并强化标题与底部实体选择键；不额外设置普通、稀有、史诗标签，重随与放弃保持为独立实体操作件。

## 战斗界面位置基准

- 波次面板：顶部居中。
- 军需铺：左上角，使用商店图标。
- 设置与性能信息：右上角。
- 能量条：手牌正上方。
- 手牌：底部居中，保留现有卡牌尺寸与操作方式。
- 牌堆：底部两侧。
- 单位信息：右侧，避开顶部波次面板。

窄屏允许把左上角军需铺下移到波次面板下方，但不能与波次或设置按钮重叠。

## 实现入口

- 战斗 HUD 结构：`index.html`
- 战斗 HUD 最终视觉覆盖：`src/battleHud.css`
- 卡牌结构与交互：`src/systems/CardSystem.js`
- 波次与附魔数据：`src/systems/Game.js`

`src/battleHud.css` 在全局样式之后加载，是当前战斗 UI 的最终视觉层。后续迁移时优先提取公共设计变量和组件类，不要继续在 `src/styles.css` 末尾堆叠重复覆盖。

## 后续界面迁移检查

- 布局和信息是否仍服务原有功能，而不是为了统一外观强行改版？
- 是否使用暗色哑光主体、切角和克制的实体厚度？
- 图标是否准确表达功能？
- 是否只在必要位置使用功能色？
- 是否避免玻璃拟态、羊皮纸、强发光、胶囊标签和大圆角卡片？
- 文字在复杂战场和低分辨率下是否仍清楚？
- 交互状态是否包含默认、悬停、按下、选中、禁用？
- 经过桌面、900px 以下和 560px 以下三档实际画面检查后再完成迁移。
