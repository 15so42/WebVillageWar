# 防御终端、维修调度与扩张压力（2026-10-05）

## 必须一并阅读的追加设计

用户追加问题：有限地图的资源全部采光后如何持续经营。执行本轮前必须阅读 docs/DSH_RESOURCE_SUSTAINABILITY.md，将种植续航、地表耗尽后的慢速深采、材料回收及基础恢复路径纳入同一轮实现与验收。食品、燃料和维修的持续消耗必须有可经营的长期资源来源。该文档的验收结果写进本轮结果报告，不另等 Codex 审查。

## 委托与范围

用户要求：防御建筑有多种类型、多种级别；建筑脱战后健康不足时请求维修，傀儡按优先级处理；增加能持续驱动经营的生存压力，纠正基地供能过于宽裕的问题。

Codex 负责本文设计，DSH 全权负责实现、参数选择、测试、修复与验收。执行模型固定为 CommandCode 的 deepseek/deepseek-v4.1-flash。不要等 Codex 检查，不询问用户中间决策。保护所有既有未提交改动；UTF-8；禁止提交、推送、PR、公开部署、改远程设置和创建其他 AI 子代理。遵守项目工程与美术约束，采用当前海岛生存玩法。

本任务在上一轮远征任务执行器结束后开始，不能与它并行修改工作树。首先读取 docs/DSH_GAMEPLAY_RESULT.md（如果存在），对未完成的相关基础问题自行收尾，尤其真实招募单位装备识别、最终浏览器验收和测试假通过问题。再实施本文。不要重复全仓库阅读，按模块读取必要片段。

本轮完成下述三条互相连接的循环后结束，额外想法只留在结果文档：

1. 防线选择与升级：按敌群选择不同防御终端，投入建设与供能，而非无限堆一种塔。
2. 战后恢复：建筑损坏 → 脱战请求 → 傀儡带材料维修 → 消耗资源和劳动力 → 准备下一夜。
3. 扩张负担：更多人类部队需要更多口粮；更多生产、防御与傀儡需要更多燃料供能和维修产能。

## 一、防御终端：三种定位、三级投资

先核实当前箭塔、弩炮的真实数据、建造、耗能、攻击和模型入口。保留其一级原有战斗定位与正常行为，不重写稳定攻击链。

| 类型 | 主要用途 | 代价与弱点 |
| --- | --- | --- |
| 箭塔 | 高频单体，处理轻甲小怪，低成本铺防线 | 重甲与大群时效率低，血量和射程不占优势 |
| 弩炮 | 慢速重击与较远射程，针对重型敌人 | 成本高、转火慢、容易浪费伤害，不能成为最佳清杂塔 |
| 震荡塔（新增） | 短中距离、小范围魔力脉冲，处理密集敌群 | 对单体效率低于箭塔；较高功率，约同级箭塔的 1.8 倍；射程短于弩炮 |

震荡塔通过现有 AttackSystem / CombatSystem / TargetingSystem 接入，采用清晰的小范围魔法伤害；可复用已有短减速规则，最多 25%、约 0.7 秒，不做持续锁死。攻击间隔约 2.5 秒，作用半径约 2.2 米作为起始调参值。DSH 根据现有敌人血量与抗性决定具体伤害，使三名聚集敌人时优势明显，对一名敌人时不能压倒其它塔。单位和预警尺寸按真实半径一致。VFX 复用共享材质与对象池，正常深度遮挡，不加全屏 Bloom 或高频资源创建。

每类有 I / II / III 级；升级在同一建筑原地进行，不让玩家拆塔重新放置，不制造瞬间满血、回满耐久或免费供能漏洞。

- I 级是可负担的早期选择；II 级需要稳定铁矿与木炭生产；III 级需要科研与持续后勤。
- 普通升级数值起点：II 级最大生命约一级 ×1.3、伤害 ×1.2、射程 +0.4；III 级最大生命约一级 ×1.6、伤害 ×1.45、射程 +0.8。三级倍率相对一级，不在二级上再次相乘。功率约为一级的 1 / 1.2 / 1.45；DSH 可以根据实际测试调整，但必须记录最终值及理由。
- 成本以现有对应建造成本为参照，使用木材、石料、铁矿、木炭等真实资源；不能只要求更多魔核。升级是逐级投资，材料原子扣除、不能跳级、不能重复付费或重复叠加。
- 升级有短施工时间，期间该塔停火；被攻击则暂停施工，不能把升级当作战斗中的免费治疗。取消/摧毁时材料结算沿既有建设规则并明示；确认本项目退款规则后复用，不另外发明规则。
- 升级完成保留升级开始时生命、耐久和活动魔力的绝对值，并限制在新的上限内；新增容量部分不会自动填满。重载/重复刷新不会再增长属性。
- II 级由完工科研站提供资格；III 级由本类 II 级、对应路线全线清除与完工科研站提供资格：箭塔对应东岬线，弩炮对应北岬线，震荡塔对应南林线。西岭采集科技支撑成本，保持其经济定位。
- 既有哨站测距与塔升级使用不同属性来源、可正确叠加；它对哪类塔有效以现有科技说明为准，不能悄悄扩大。
- 轮廓和材质表达等级：一级木结构，二级铁加固，三级石基与更明确的机械构件；三种塔在游戏相机距离下可辨。复用现有低模资源、共享几何与材质，不能靠悬浮文字或颜色换皮充当全部差异。
- 建筑菜单显示类型、等级、用途、下一等级材料/资格、当前耗能和状态。不要恢复旧卡牌/商店界面。

## 二、建筑脱战请求维修，傀儡自主按优先级处理

先检查并复用已有恢复、维修、建设、库存、作业任务与预留机制；新增规则不要另造第二套抢任务和移动系统。

### 请求生命周期

范围是玩家的已建成、存活建筑，包括基地与供能、生产、防御建筑；施工未完成不能一边建设一边被当成健康不足维修。生命低于最大值就登记缺口；已支持结构耐久的建筑也可登记耐久缺口。满状态、被摧毁、换队或失效时移除请求，不能复活建筑。

“脱战”默认是最后受伤或发起攻击至少 8 秒。受伤时登记待处理请求，脱战前不执行；重新交战时暂停维修、解除安全作业状态，保留实际已修复量，不能继续站在炮火里修。威胁检查复用索敌的局部查询，不能对每栋建筑每帧扫全部敌人。

请求按建筑 id 唯一管理，重复受伤只更新一份；全局事件登记加有限频率队列更新，默认不高于 0.5 秒一次。死亡、重开、快照与销毁正确清理。

### 分派与优先级

- 逃生、安全与既有紧急补能规则优先；玩家明确的移动/攻击/驻守/强制任务不会被常规自动维修抢走。
- 脱战后生命比例 <35% 的关键建筑是急修；默认重要度：基地 > 魔力炉与关键供能节点 > 防塔 > 食物生产/食堂 > 普通生产与其它建筑。
- 其次是普通维修；在同一紧急等级里考虑缺损比例、距离与等待时间，长时间请求不会永久饿死；排序和阈值全部可配置。
- 默认每栋建筑同时只有一名傀儡预留和维修，基地等大型结构可配置为两名。每名傀儡只持有一项当前维修任务，断路、无法取料、单位死亡或取消时及时释放预留。
- 维修与施工/采集/搬运的相对优先级接入既有作业优先级。紧急燃料运输不能因常规维修被长期饿死，普通低损维修不能把整个生产链拖停。
- 傀儡需要实际移动到建筑旁，材料实际从可达库存或背包取用；修复速度、材料用量及劳动/活动魔力消耗配置化。与现有维修工具兼容；如需工具，首轮须有可实现制作路径。

### 维修必须有经营代价

修理消耗木材、石料或铁矿，随建筑材质和修复量决定，不能免费补满。采用批量材料提供有限修复额度或等价守恒结算，避免每帧把小数四舍五入为一个材料，也不能扣一个材料就无限修复。剩余额度和中断结算规则必须明确且可验证。

材料不足时保留请求为“待材料”，告知具体缺少什么并允许转做其它任务；不要反复取不存在的材料、锁住全部工人或持续弹窗。多个傀儡不能各扣一次材料修同一份缺口。

建筑状态可显示“交战中等待 / 待维修 / 缺材料 / 傀儡维修中 / 已恢复”。用少量克制的状态标记，维修动作与粒子复用既有材质；没有任务时不常驻大图标。

## 三、多重压力来自扩张的真实负担

不是给所有单位再叠几根持续下降的条。要形成能预判、有解决办法、由经营规模带来的压力。

### A. 收紧基地免费供能，保留可靠起步

当前活动魔力 activityMana、供能功率与符文石 mana 是不同机制。调整供能链不能混用符文魔力、附魔成长或魔力石容量。

目标：基地持续供能能支持一名起始傀儡基本作业，但无法同时轻松支撑多傀儡、熔炉和防塔。扩张必须依靠木材 → 木炭 → 魔力炉与物流。优先调整已有基地输出功率、活动魔力初始储备和设施消耗参数，不增加新货币或另一根魔力条。

- 起步活动储备应覆盖约 4–6 分钟基础发展，至少能完成燃料链的自启动。单傀儡不能在做好熔炉前永久断电卡死。
- 魔力炉保持已有自启动能力，配方不能要求“先有木炭才能制造烧炭供能链”；既有燃料循环净产出为正。
- 三种塔的级别越高、数量越多，需要更高燃料吞吐；停掉部分防塔能给生产让电，现有逻辑门、开关与运输系统因此有实际用途。
- UI 同时显示活动储备与净供需，避免“大容量”看上去等于“无限持续功率”。缺口提示说明燃料、运输或输出瓶颈；估计剩余时间时只用真实消耗率，零消耗显示稳定而非除零/无穷。
- DSH 记录修改前后参数与实际自启动模拟，证明“起步可玩、扩张要供给”，不能仅把数字随意调小。

### B. 人类部队的口粮与供餐；傀儡不吃饭

增加真实食物后勤，以现有食堂承担供餐，复用库存、运输、生产、种植和资源采集流程。傀儡由魔力、工具/武器损耗和维修负担驱动，不新增人的饥饿与睡眠需求。

人类或需要饮食的招募兵种通过数据标记 foodConsumer，敌人、野生动物、中立待招募、建筑、傀儡不计算玩家饥饿。成功归队时初始化需求；不能把全部 canMove 单位直接当成人类。

- 饱食度 0–100，初始 100；默认每分钟 -12，消耗随模拟时间、暂停规则正常。可用需求系统只管理需要饮食的单位，不每帧扫全世界。
- 饱食度 ≤60 且背包有口粮时自动消耗一份、恢复 40，不能超上限，不能重复扣费；可在战斗中吃随身口粮，不改变当前指令。
- 没有随身口粮时，空闲单位可使用食堂供餐预约和实际移动；不会因吃饭抢走玩家强制攻击、驻守和远征命令。前线应通过携带口粮或运输补给解决，不能从远处基地隔空吃库存。
- <25 时攻速 ×0.85、自然恢复效率减半；0 时攻速 ×0.70、停止自然恢复。两个等级互斥，不叠成更重惩罚。吃饭恢复后即时撤掉修正，独立属性来源幂等。不额外扣生命，不让全军因菜单/离线计时突然饿死。
- 饥饿和现有耐久、供能互不替代；饱食度只在人类单位详细状态显示，HUD 以口粮库存、预计供养人数/时间和缺粮部队数量汇总，不塞全军条形面板。

食品链先做一种，避免大规模农场模拟：

1. 新物品“谷物”和“口粮”。若项目已有合适食物数据与生产链，复用并统一命名，不建立平行食物库存。
2. 菜圃是可建造的单块作物设施；种植、生长、成熟复用已有种植/资源节点架构。一个逻辑作物节点可以用数株低模植物表现；成熟后必须由傀儡实际采收，再搬运。
3. 起始调参：一块菜圃约 120 秒成熟一次，总产谷物 3；收完再进入生长周期。不是每株分别产 3，不能把视觉植株数当倍增产量。采集加成与节点剩余量守恒，不能额外复制作物。
4. 食堂加工起始配方：谷物 2 + 木炭 1 → 口粮 2，约 12 秒，并接入已有活动魔力、进料、产物与物流。食堂原有治疗/恢复功能兼容，不能用旧免费治疗代替食品。
5. 以上产能目标是一块菜圃在稳定采收加工后供养约 4–6 人。DSH 可以按真实行动时间调整，需记录理由；多个军团需要增加耕作、加工和运输能力，而非一个设施养全图。
6. 起始基地库存补 12 份口粮，帮助首次招募平稳进入食品链；不要附带新增开局人类护卫。新开局依然一名木傀儡、既有工具、八巢与三处营地。
7. 菜圃、加工配方可在早期获得，不绑远处巢穴或高阶科技。建造成本使用木材、石料、纤维等可采资源，确保首次招募后能在吃完初始库存前建立闭环。

“疲劳”的节奏先由补能、损耗、维修与供餐中的停工/休整体现；本轮不再添加独立睡眠条、床铺、疾病、氧气或季节系统。目的是让白天采集与维护、夜晚防御、远征补给相互牵制，而非给玩家增加无意义的点击。

### C. 驱动力表达

- 远征面板把不同路线奖励连接到防御升级资格与生产能力；仍保留玩家自主选线。
- 白天目标提示基于真实缺口：关键建筑待修、供能净缺口、即将缺粮、装备准备、当前远征目标。只给最紧要的一到两项，不轮播大量告警。
- 夜前提醒“修好防线、备燃料、备口粮”；攻下一条路线得到能力和新劳动力，但也产生更多维护与补给需求。
- 允许玩家关闭建筑自动维修或调整默认维修重要度，也能开关防塔，为主动安排劳动与供能留空间；提供合理默认值，不强制每局手动配置。

## 架构、性能与持久化

数据与可调参数集中在现有 gameData / BALANCE 和必要的新数据模块；纯规则与运行时分离。新增系统按职责独立，例如防御升级规则、维修任务协调、部队需求；Game 只做必要接线，不堆 HTML、队列和 WebSocket。

复用 UnitRegistry 生命周期、WorkSystem 任务、Attack/Combat 属性、库存与生产、供能与食堂、种植、场景样式与共享 VFX。能力来源 id 唯一，可撤销、可快照、可重载，不能改共享单位定义来升级某一栋塔。

默认事件驱动或 0.5–1 秒有限采样；先消除重复扫描/创建资源，再降低频率。队列预留、升级进度、剩余维修额度、饱食度与作物生长按已有存档/快照能力持久化。重新开始清理监听、任务、DOM 和属性来源；现有联机入口与经济规则不被悄悄启用或改写。工具材料、状态 UI 和吞吐统计读取真实数据，不写死第二份。

## DSH 必须自行完成的验收

1. 所有修改 JS 语法检查、生产构建、相关旧回归及新的有意义规则/运行时测试。修复失败，不降低断言或删除旧测试；成功后只在新增改动影响它时重跑。
2. 三塔三等级真实建造/升级，拒绝跳级与重复扣费；升级施工、交战暂停、材料不足、摧毁与快照行为；北线射程科技与等级不重复叠加；视觉在实际游戏相机可辨。
3. 建筑受伤后登记唯一请求，8 秒内不修，脱战后材料与工人到场实际修；再交战暂停；优先急修供能源/基地；多个工人不重复预留/扣费；无料、断路、死亡、取消、重开不永久锁住任务；满血与死亡正确清除。
